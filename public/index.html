      No certificate yet? Create a request (CSR) for IT

      The private key is made and kept on this server. Send IT the request; when the certificate comes back, upload just that file above (and its chain, if they send one). It pairs with the key by itself.

      Download the request (.csr)

    2. 2 Turn on HTTPS next to http

      Same address and port, with https://. Everyone on http carries on as before.

    3. 3 Test it

      Open the HTTPS address

    4. 4 Switch to HTTPS only

      Then plain http answers with a redirect to https, and reports switch to the new address by themselves.

    5. 5 Harden

      • Always on over HTTPS: session cookies are Secure, HttpOnly and SameSite.
      • A strict Content Security Policy, no framing and no MIME sniffing, on every page.

        GitHub
        
              
        A token with read access to the repositories (and read:org for verified-domain emails). Stored on this server like the SMTP password, and never shown again.
        
              
        
                
                
                
                
              
        
              
              
        
                
                
              
        
              
        
                
                
                
              
        
            
        
            
        
              
        GitLab, Azure DevOps and Bitbucket
        
              
        Each token is stored on this server like the SMTP password, never shown again, and only ever sent to its own host. Read-only scopes are enough. Or set them in the .env file (GITLAB_TOKEN, AZURE_DEVOPS_TOKEN, BITBUCKET_TOKEN…).
        

              
        
                GitLab 
                
        A personal, group or project access token with read_api and read_repository. Blame through the API, GraphQL user batches, profiles, and commits by name.
        
                
        
                  
                  
                  
                  
                
        
                
        
                  
                  
                  
                  
                
        
              
        

              
        
                Azure DevOps 
                
        A personal access token with Code (read), Graph (read) and Identity (read). Azure DevOps has no blame API: blame uses git on a clone made with this token. Usernames: the organisation directory, identity search, commits.
        
                
        
                  
                  
                  
                
        
                
        
                  
                  
                  
                  
                
        
              
        

              
        
                Bitbucket 
                
        Cloud: an app password (with your username) or a workspace/repository access token, read access to repositories and the workspace. Bitbucket Cloud has no blame API, and never shows users' email: blame uses git, and usernames are matched through commit authors. Data Center: an HTTP access token; blame through its API, and its user directory.
        
                
        
                  
                  
                  
                  
                  
                  
                
        
                
        
                  
                  
                  
                  
                
        
              
        
            
        
            
        
              
        More connections to the same host
        
              
        A second GitHub (an Enterprise server next to github.com, or another organisation), GitLab, Azure DevOps or Bitbucket: the same variables with a number, in the .env file or uploaded under Settings. Each repository is blamed with the connection for its host (and its organisation, group or workspace, when two share a host).
