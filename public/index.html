Scan initiators

Checkmarx records the person who ran a scan as a username, which is not always an email address. These rules turn it into one; the dashboard shows what each project resolved to.

Mail template

Values are inserted with {{name}} and HTML-escaped; {{{name}}} inserts raw HTML. Repeat a list with {{#projects}}…{{/projects}}, and show a block only when something is empty with {{^projects}}…{{/projects}}.

Available variables

Automation

Checks on a timer and mails the moment a finding crosses one of your age thresholds. Each finding is reported once per threshold, so a daily sweep does not re-send the same thing every day.

AI Triage & Remediation from reports

Readers of the emailed report can run Checkmarx One AI Triage and AI Remediation through this server, on its own Checkmarx One connection. Both use credits, so nothing runs until you allow it here.

Branding

The app name and logo appear in this app; the company name and logo also head every reminder and report. For reminders, an https logo URL is best — most mail clients block embedded images.

Links into Checkmarx One

Every finding in a reminder links straight to it in the platform. If a link lands in the wrong place, correct the template here — the example below updates as you type.

Reminder server address

Put into every HTML report, so anyone who opens it can connect and triage: the address people's browsers use to reach this server — e.g. https://cx-reminder.corp.example. Readers see it in the report and can correct it there if the server moves.

Risks endpoint

Defaults to /api/risks/. Detect probes the known paths against your tenant and reports what each returned.

Tracked reports

Each report keeps the findings its scope covered when saved and follows what happened to them — triaged, confirmed, proposed not exploitable, or no longer detected — plus how many findings the same filters match today. Save one from the Dashboard with Save as tracked report.
