# MZ-01.01.19: the scan of the Fusion credits code

Checkmarx One scan `09e66411` of this release's code (commit f0ab2a5, the Fusion credits code complete; SAST, SCA, IaC, containers, secret detection, API security) lists **226 results: 1 critical, 6 high, 94 medium, 122 low, 3 info**. The scan before it, `fb266f9f` of MZ-01.01.17's first commit, listed 217; the critical and the six high are the same results, judged in [MZ-01.01.17's review](mz-01.01.17-review.md).

**16 are reported for the first time**, and 7 of fb266f9f's are no longer listed. Nothing in Checkmarx One is marked: every result is still **To verify** there, to be recorded by someone with the right to change a SAST result's state.

## The 16 first reports

| Results | Query | Where | Judgement |
| ---: | --- | --- | --- |
| 10 (medium) | `PCI_Data_Exposure` | `src/routes/fusion-credits.js`, lines 82–150: the rows and the view the Fusion credits page shows | Not exploitable. "Credits" are Checkmarx One AI credits (allocated, used, left, rates per 10,000 lines), not payment cards. The view is sent only to someone signed in with **credits.view**, as Credit Control's figures are; no card or account number exists anywhere in the server. The same query on the same words was judged in MZ-01.01.17's review (33 results). |
| 2 (low) | `Log_Forging` | `src/routes/people.js`, lines 142 and 164 (an Admin changing someone's profile) | Not exploitable: the flow ends at the server log's cleaner, which MZ-01.01.17 put on that line. The changed flow is why the engine reports it under a new identity. |
| 3 (low) | `Privacy_Violation_in_Logs` | `src/routes/people.js` line 182, `src/backup.js` line 168 | Not exploitable. In people.js an email address, cleaned, goes to the server's own log, which no route serves (judged in MZ-01.01.17's review). In backup.js the backup key is used to derive the decryption key and never written anywhere: the catch around it logs nothing. |
| 1 (low) | `Information_Exposure_Through_an_Error_Message` | `src/routes/hands-off.js` line 223 (an emailed one-click link) | Not exploitable: since MZ-01.01.17, only a refusal raised on purpose is shown to the reader; anything else is "something went wrong" and the details go to the server log only. |

The six low results are in lines MZ-01.01.17 changed after its scanned commit; they are the earlier results' flows reported again with the hardening in them.

## What this review did not establish

- The data flow was not fetched from Checkmarx One for these 16; each was judged from the flagged line and its callers.
- Which 7 of fb266f9f's results are no longer listed was not checked one by one; the critical and high counts are unchanged.
- The scheduled Fusion scan's request (`type: ai`, `fusionEnabled`, `llmModel`) was tested only against CxMissionZero's test double of Checkmarx One.
