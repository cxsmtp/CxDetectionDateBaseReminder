## The report's levers, checked by hand

A report made with its levers carries one script, so it was reviewed beside the scan:

- **What runs.** The file's content security policy allows one script, by its SHA-256 hash, and nothing else: no other script or inline handler, no connection (`connect-src 'none'`), no form, no frame, nothing loaded. The script is this server's bundle of public/calculator modules, built at start.
- **What it writes.** Every name and figure goes through the report's escaping, as in a report without levers; the figures it carries are JSON with every `<` written as `<`, so they cannot end their element. A changed figure (a typed rate, a project's scans) is cleaned by the model's own functions before it is used.
- **What is emailed.** The email route took only files with no script. It now also takes a report with its levers, but only when its one script is this server's own to the byte, its policy the expected one and its figures valid JSON; anything else in the file is checked as before, and an in-page `#` link is the only address allowed. test/report-levers.test.js tries an added script, a changed script, a looser policy, an image and a link to another site: each is refused.
- **What is left out.** Without project details, no project's name, id or file is in the report, its figures or its PDF (projects are kept as nameless rows of their count and lines); the test checks every project name against the file.
