## Hardened in 955a6c5

| Severity | Where | Result | What changed |
| --- | --- | --- | --- |
| Critical | `test/calculator-git-count.e2e.test.js:153` | Secret detection (generic API key) | A fake token, written out, that the "wrong token" case sends on purpose to the test's own git host on 127.0.0.1: 16 characters with "wrong" in it, where a real GitHub token has 36 more characters and a checksum. | High | `src/fusion-git.js:657` | Race Condition (TOCTOU) | The repository's host name was checked (never a link-local or cloud metadata address) and then looked up again by git. git is now held to the addresses checked (`http.curloptResolve`, git 2.37 and later), as webhook calls already are (src/govern/notify.js:73). Before that, the second look-up could only reach a host on the allowed list, over https with its certificate checked and no redirects, so a metadata service (plain http) could not answer. |
| High (2) | `test/fake-git-host.js:36` | Path Traversal | The test's git host, on 127.0.0.1 for the length of a test. URLs already normalise `..`, and git http-backend refuses a path with `..`; probes outside its folder got 404 and 500 with nothing in them. It now refuses any encoded character or `.`/`..` segment with 400, accepts plain organisation names only, and no longer decodes the path for git, which also stops a malformed `%` from throwing inside the handler. test/calculator-git-count.test.js checks both. |
| Medium | `src/fusion-git.js:302` | Weak Cryptographic Hash | Not a security use: a key so that two copies of one file are counted once, in a folder of the person's own code (git's own object ids do the same with SHA-1 on the repository path). It is SHA-256 now. |
