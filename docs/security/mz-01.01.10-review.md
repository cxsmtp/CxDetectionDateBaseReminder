# MZ-01.01.10: the scan and an independent review of the new code

Two checks were made on this release before it was merged: a Checkmarx One scan of the release branch, and a review of the release's own code by a second reader who was given the code, not the conclusions.

## The Checkmarx One scan

Scan 98d2cbd0 of the release branch (9f14672), with SAST, SCA, KICS, containers, secret detection and API security, found 32 results: 1 critical, 5 high, 9 medium, 16 low and 1 info. The AI engines that earlier scans also ran cannot be asked for through the connector, so this scan is without them; the last scan with them is e4657d28 of MZ-01.01.08.

- **New: 1.** A made-up address with a username and a password in it, written out in a test (`test/projections.e2e.test.js:288`), which secret detection reads as a credential. It is no secret: the test checks that the calculator's address refuses one. The address is now put together in code (96225aa), as the other tests do.
- **Recurrent: 31**, every one judged in earlier reviews, in code this release does not change:
  - **The container result (critical)**: CVE-2026-4738, the Alpine zlib advisory judged in MZ-01.01.08 (a GDAL module the image does not have; the image takes Alpine's fixes when it is built).
  - **Four Reflected_XSS results (high)** in `src/govern/routes.js` (now at lines 394, 423, 437 and 549): the sink is `res.json()`, sent as `application/json` with `X-Content-Type-Options: nosniff`, on routes that need a Govern permission ([MZ-01.01.00](mz-01.01.00-not-exploitable.md)).
  - **The KICS result (medium)**: ports 80 and 443 published for the Caddy proxy, which is what it is for.
  - **The SAST results left (medium and low)**: the certificate checks that only read a chain to show an Admin why it is untrusted (`src/trust.js`, `src/network.js`), the load-test mock (not in the image), the calculator's local launcher, error texts that are scrubbed or fixed, the empty default of the mail password, and the report's own link check ([MZ-01.01.00](mz-01.01.00-not-exploitable.md), [MZ-01.01.02](mz-01.01.02-review.md), [MZ-01.01.03](mz-01.01.03-review.md), [MZ-01.01.08's status](../status.md)).
- **The release's own code has no result in it**: `src/state-file.js` and the stores that use it, `src/instance-lock.js`, `scripts/restore.mjs`, the licence in `src/activation.js`, and the limits on requests from people who are not signed in.

Scan dc0b5c87 of the final code (96225aa, with that fix and the independent review's fixes below) found 31 results: 1 critical, 4 high, 9 medium, 16 low and 1 info. None is new: they are the 31 above.

Marking the results judged not exploitable in Checkmarx One is a separate step, done with the maintainer's confirmation; the release does not wait for it.

## The independent review

The reader was asked for defects that can be exploited or lose data, in the state files, the lock, the restore, the licence, the limits on unauthenticated requests, the Labs permissions, the calculator's address and the workflow. No critical or high finding; seven medium or low.

### Fixed in the release

| Severity | Where | What was wrong | What changed |
| --- | --- | --- | --- |
| Medium | `src/server.js` (`auditRefusedRequest`) | Someone holding one emailed report could repeat a request that is refused as a whole (an altered report identity, AI Triage switched off), each time adding an audit entry listing up to 500 findings: the audit log is never trimmed, so the disk could be filled. | Refused requests from a report are listed at most 10 a minute for one report and 40 in all, each with the first 20 findings and a count of the rest; the others are counted in one line. Refused product activation codes and refused sign-ins have counts of their own. |
| Medium | `src/server.js` (`/api/licence/activate`), `src/activation.js` | Codes are not tied to one server. Any in-date product code replaced the one in force, on a page anyone can reach, so an older, shorter code could cut the date short; an older "on" code could bring back a feature a later "off" code had turned off. | A code issued before the one in force for the same thing is refused. On the deactivated page a product code is taken only if it runs longer than the one in force. |
| Low to medium | `src/instance-lock.js` (`look`) | A lock that could not be read looked the same at every look, so after the stale time it was taken over, and the server that held it then stopped itself. | It is held, and never taken over: a starting server waits, then refuses and says why. |
| Low | `src/instance-lock.js` (heartbeat) | The heartbeat wrote its next lock under a fixed name, through whatever was there: another local user able to write in the folder could leave a link there and have a state file overwritten. | A new name nobody can guess at each beat, created only if nothing has it. |
| Low | `scripts/restore.mjs`, `src/backup.js` | A restore runs without giving its lock's timer a turn; one longer than the stale time could lose the folder to a server started meanwhile. | The restore beats its lock between files. |
| Low | `src/state-file.js` (`readState`) | A state file put right from its last good copy was not written back, so a backup made before that store's next save left it out. | The copy is written back as the file. |

One more change came from the review's open question: settings a new version cannot load no longer stop the start as a damaged file does (exit code 78, never rolled back), so after an update the launcher goes back to the version before.

### Left for a decision

| Severity | Where | What it is |
| --- | --- | --- |
| Low to medium | `src/activation.js` (`#seal`) | Feature and tenant activations entered before this release are kept without their signed code and are still trusted, so someone who can write the data folder could write one by hand. The product licence is not affected: it needs its code. Closing this means every feature and tenant code is entered once more after updating. |

### Checked and found sound

- **Request sizes**: 512 KB on the report routes, 64 KB at sign-in and the licence page, 40 MB only for someone signed in who may use the calculator.
- **State files**: temporary files have names nobody can guess, are created exclusively with mode 0600 and flushed; last good copies and damaged files keep that mode; no copy is kept where a secret was removed on purpose.
- **Restore**: names are checked twice, nothing leads out of the folder, last good copies are moved aside.
- **The product licence**: the date and what a code is for are read from the signed code; edited entries and codes for something else are refused.
- **Labs permissions**: stricter than before; the migration only keeps what a role could already use.
- **The calculator's address**: http or https only, no username or password in it, checked again when loaded, set only by an Admin.
- **The workflow**: the tests run with a read-only token; an image is published only after both jobs pass, and never from a pull request.
