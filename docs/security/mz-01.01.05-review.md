# MZ-01.01.05: results of the scans

Scan 61a87e72 of main (98c892d, MZ-01.01.03's code) ran every engine, the AI engines and API security included, and found 73 results: 5 critical, 29 high, 26 medium, 12 low and 1 info. That is 63 SAST, 8 OpenSSF Scorecard, 1 KICS and 1 SCA; API security and AI supply chain completed with nothing to report. 53 had been judged before ([MZ-01.01.04](mz-01.01.04-review.md) and the reviews before it), by file and query. 20 were new: each was traced through its data flow and checked against the code of this release. 3 were real and are fixed here, 2 more are hardened although not exploitable, and the rest are not exploitable for the reason given, 4 of them results judged before that Checkmarx One gave a new id. Scan 3ce920fc of this release's final code (eeb5533, SAST, SCA, KICS, containers, secrets and API security) was still waiting in Checkmarx One's queue five hours after it was started, and the release was merged before it ran, at the owner's call; its results are reviewed with the next release. Line numbers are those of this release's code. Back to [status](../status.md).

Checkmarx One refuses SAST state changes from the connector's account (it lacks SAST triage rights), so the results judged not exploitable wait for an administrator to mark them, as those before them do.

## Fixed

| Severity | Where | Result | What changed |
| --- | --- | --- | --- |
| High | `src/mail-inbox.js:113`, `:192` | Cleartext Transmission | The hands-off reply reader and the start-up backup search read the mailbox over IMAP. On a port other than 993 the mail library moved to an encrypted connection only when the server offered it, so someone on the path who removed the offer received the mailbox password. Shown with a test server on this machine. IMAP now requires STARTTLS whenever the connection is not encrypted from the start (`doSTARTTLS`), and a server that does not offer it gets its own **How to fix it**; the IMAP twin of MZ-01.01.03's SMTP fix. test/outbound-tls.test.js checks that a server offering no STARTTLS never receives the password. |
| High | `src/govern/store.js:202` | Missing Authorization | Someone allowed to manage budgets but not to enforce them could widen an Enforce budget already set (25 projects to 10,000, members and subgroups, a lower amount), skipping the confirmation that only an enforcer gives. A change that widens what an Enforce budget restricts now needs **Enforce budgets**, from the form, the bulk edit and the CSV import alike; switching to Monitor, pausing and narrowing still don't. Tested in govern-store, govern-csv and govern.e2e. |
| High | `public/calculator/standalone.js:299` → `public/calculator/page.js:778` | Cross-site Scripting | Restoring a backup in the one-file calculator stored its customers without the checks a save gets, and a few numbers were written into the page unescaped. The file's content security policy allows no script that is not its own (hashes, no inline handlers, no forms), so at worst markup from a backup the person chose could show. Restored customers now go through the same checks as a save, and every value written into the page is escaped. test/standalone-calculator.test.js restores a hostile backup and renders it. |

## Hardened

| Severity | Where | Result | What changed |
| --- | --- | --- | --- |
| Critical | `src/iam.js:297` | Improper Authentication | Not exploitable: a sign-in with a Checkmarx One API key is exchanged only at this server's own Checkmarx One, and trusts only what that tenant's IAM says (as judged for `cxone/client.js:82`). But every API key signs in through the same client, `ast-app`, so an Admin who listed `ast-app` as someone's alias would have let every key holder in the tenant sign in as that person. `ast-app` is now refused as an alias, a client id never matches anyone, and an email the token marks as not verified is ignored. The People page and the user guide no longer offer client ids. |
| Critical | `test/connection-guard.e2e.test.js:51`, `test/update-handover.e2e.test.js:112` | Use of Hard-coded Credentials | Test signing keys for servers started on this machine during a test, not in the image. Ten end-to-end tests now make their key at run time, as MZ-01.01.02 did for others. |
| Medium | `src/fae-flush.js:856` | Sensitive Information in Log | Already redacted (storage signatures); the debug log, readable only with the Checkmarx One integration permission, now also hides tokens, passwords in addresses and secret query parameters, one text at a time. |
